프로젝트 목표

1인 가구 증가와 물가 상승으로 장보기 예산 부담이 커지고, 구매한 재료를 다 활용하지 못하는 문제가 생깁니다. 카메라로 담은 상품을 자동으로 인식해 금액을 바로 보여주고, 보유 재료 기반 요리를 추천해 예산 관리와 재료 활용을 함께 돕는 것을 목표로 했습니다.

목표 요약: 상품 인식 → 자동 장바구니 등록 → 실시간 금액 계산 → 요리 · 부족 재료 추천.

상품 탐지 · 자동 장바구니 등록

YOLOv8n으로 상품 10종을 인식하고, 탐지가 확정되면 장바구니에 자동 등록합니다.

수량 · 총 금액 실시간 계산

상품 · 가격 DB를 기반으로 수량과 총 금액을 즉시 갱신합니다.

보유 식재료 기반 요리 추천

장바구니에 담긴 재료로 만들 수 있는 요리 5종을 추천합니다.

부족 재료 자동 안내

요리별 필요 재료와 보유 재료를 비교해 부족한 재료를 자동으로 알려줍니다.

주요 문제 해결 사례

문제 1. 오탐이 곧 장바구니 금액 오류로 이어짐

상황: 카메라에 상품이 잠깐 스치거나 비슷한 상품이 잘못 인식되면, 장바구니에 잘못된 상품이 담겨 금액이 틀어집니다.

해결: 상품별 신뢰도 임계값을 튜닝하고, 같은 상품이 1초 이상 유지될 때만 장바구니에 등록하도록 했습니다. Recall을 일부 포기하더라도 Precision을 우선하는 운영 기준을 택했습니다.

결과: 운영 기준 Precision 94.70% (Recall 57.66%, mAP50 82.20%)로 장바구니 금액 오류를 최소화했습니다.

문제 2. FastAPI 실행 시 ASGI Application 로딩 오류

상황: uvicorn main:app 실행 시 Attribute "app" not found in module "main" 오류가 발생했습니다.

원인: main.py 내 FastAPI 인스턴스(app) 선언과 엔트리포인트 모듈 구조에 문제가 있었습니다.

해결: FastAPI 인스턴스를 올바르게 선언하고 모듈 구조를 정리해 정상 실행되도록 했습니다.

배운 점: Uvicorn이 Python 모듈과 FastAPI Application 객체를 어떻게 로딩하는지 구조를 이해했습니다.

성과

94.70% Precision (임계값 튜닝 후 운영 기준)
57.66% Recall (정밀도 우선 전략)
82.20% mAP50
10 + 5 상품 10종 인식 + 요리 5종 추천 로직 통합

회고

증강과 하이퍼파라미터를 늘려도 성능이 비례해서 좋아지지는 않았습니다. 오히려 서비스 목표(정밀도 우선)에 맞는 운영 지표를 고르는 것이 더 중요하다는 것을 확인했습니다. 장바구니 서비스에서는 놓친 상품보다 잘못 담긴 상품이 사용자 신뢰를 더 크게 떨어뜨리기 때문에, 정밀도 우선 전략으로 오탐을 최소화했습니다.
