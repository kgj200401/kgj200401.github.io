LLM 평가 설계

팩트체크 · 교차 평가 · 외부 심판 · 사람 블라인드 4가지 평가를 설계하고 실행했습니다.

주요 문제 해결 사례

문제 1. 로컬 LLM이 한국어 질문에 중국어를 섞거나 엉뚱하게 답변

상황: 직접 양자화(GGUF Q4_K_M)한 로컬 LLM이 한국어 질문에 중국어를 섞거나 질문과 무관한 답을 생성했습니다.

원인: Ollama 등록 시 채팅 템플릿을 지정하지 않아, 모델이 기대하는 입력 형식(ChatML)과 실제 입력이 일치하지 않았습니다.

해결: 토크나이저 설정을 확인해 올바른 템플릿을 Modelfile에 명시한 뒤 재등록했습니다.

결과: 한국어 응답이 정상화되었고, 신규 모델을 추가할 때 템플릿을 먼저 확인하는 절차를 팀 규칙으로 수립했습니다.

문제 2. 로컬 모델끼리 서로 채점하면 평가 결과를 믿기 어려움

상황: 여러 로컬 LLM의 답변 품질을 비교하기 위해 모델끼리 교차 채점을 시켰더니, 자기가 만든 오답에도 후한 점수를 주는 경향이 나타났습니다.

해결: 교차 평가에만 의존하지 않고 팩트체크, 외부 중립 심판, 사람 블라인드 평가를 함께 설계해 결과를 교차 검증했습니다.

배운 점: LLM 평가에는 자기 선호 편향이 있어, 중립 심판과 사람 블라인드 평가를 함께 봐야 신뢰할 수 있는 결론이 나옵니다.

성과

99.61% Vision 인식 정확도 (테스트 257장 중 256장, macro F1 99.63%)
53 / 54 실사 촬영 정답, 유일한 오답은 신뢰도 0.28로 임계값(0.60)에서 재촬영 요청
3.5~4.3초 LLM 평균 응답속도 (로컬 모델 4종 비교 기준)
1,482장 Synthetic 1,416장 + 실사 66장 데이터셋

핵심 성과: 신뢰도 임계값으로 불확실한 인식은 재촬영을 요청하도록 설계해, 잘못된 유물 해설이 노출되지 않도록 했습니다.

회고

팀장으로서 가장 크게 배운 점은 "측정 방법을 먼저 정해야 결론을 믿을 수 있다"는 것입니다. Vision 쪽은 synthetic 데이터로 학습하되 실사 데이터를 val/test에 배치해 실제 환경 성능을 따로 확인했고, LLM 쪽은 4가지 평가를 병행해 한 가지 평가 방식의 편향에 결론이 휘둘리지 않도록 했습니다.
