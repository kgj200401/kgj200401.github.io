Project 01

이미지 기반 VQA 멀티모달 AI 모델

제한된 GPU 자원 안에서 대규모 Vision-Language Model을 실제 추론 가능한 형태로 최적화하고, 보기 순서 편향을 줄여 VQA 정확도를 개선한 프로젝트입니다.

프로젝트 기간

2025.10

사용 기술

Qwen3-VL (32B) PyTorch Unsloth LoRA/QLoRA 4-bit Quantization

프로젝트 목표

고성능 멀티모달 모델을 단순히 실행하는 것에 그치지 않고, 제한된 VRAM 환경에서 안정적으로 추론 가능한 구조를 만드는 것이 핵심 목표였습니다. 또한 이미지 기반 질의응답(VQA) 태스크에서 모델이 정답의 위치나 보기 순서 같은 표면적 패턴에 의존하지 않고, 이미지와 질문의 의미 관계를 기준으로 답을 선택하도록 개선하는 것을 목표로 했습니다.

목표 요약: 대형 VLM을 경량화하고, 보기 순서 편향을 줄여 실전형 VQA 추론 파이프라인 구축.

프로젝트 배경

대규모 VLM은 이미지 이해와 언어 추론을 동시에 수행할 수 있어 VQA 문제에 강점이 있지만, 모델 크기가 커질수록 GPU 메모리 요구량이 급격히 증가합니다. 프로젝트 환경에서는 32B급 모델을 그대로 운용하기 어려웠고, 정확도를 유지하면서도 메모리 사용량을 낮추는 전략이 필요했습니다.

초기 실험에서는 모델이 이미지 내용을 충분히 해석하기보다 특정 보기 위치에 과도하게 반응하는 경향도 확인했습니다. 따라서 모델 경량화, 출력 안정화, 데이터 구성 편향 완화가 함께 해결되어야 했습니다.

핵심 기능

이미지 기반 질의응답 추론

이미지와 질문, 선택지를 함께 입력해 모델이 가장 적절한 답을 선택하도록 프롬프트를 구성했습니다.

모델 경량화 및 추론 최적화

4-bit 양자화와 LoRA 적용 범위 조정을 통해 제한된 VRAM 환경에서도 32B 모델을 운용할 수 있도록 구성했습니다.

보기 순서 편향 완화

선택지 순서를 무작위로 섞는 Choice Shuffle을 적용해 모델이 보기 위치가 아니라 의미적 근거를 기준으로 답하도록 유도했습니다.

역할 및 기여도

모델 성능 비교 및 벤치마킹

기여도 30%

후보 모델별로 동일한 평가 데이터와 동일한 프롬프트 조건을 적용해 추론 결과를 비교했습니다. 모델별 정답률, 오답 유형, 출력 형식 안정성을 함께 확인해 단순 점수뿐 아니라 운영 가능성을 기준으로 비교했습니다.

하이퍼파라미터 탐색

기여도 25%

양자화 적용 여부, LoRA 적용 범위, max token, temperature, few-shot 예시 구성 등을 바꿔가며 정확도와 출력 안정성을 비교했습니다. 특히 정확도 상승과 VRAM 사용량 사이의 균형을 기준으로 최종 설정을 선택했습니다.

프롬프트 및 출력 제어

기여도 20%

모델이 불필요한 설명을 길게 생성하거나 선택지 외 답변을 생성하는 문제를 줄이기 위해 답변 형식을 명확히 제한했습니다. 정규표현식 기반 후처리로 모델 출력에서 최종 선택지를 안정적으로 추출했습니다.

편향 분석 및 데이터 로더 개선

기여도 15%

오답 케이스를 확인하며 특정 보기 위치에 정답이 몰릴 때 모델이 위치 패턴을 학습할 가능성을 점검했습니다. 이를 줄이기 위해 데이터 로딩 단계에서 선택지를 섞고 정답 인덱스를 재매핑하는 로직을 구현했습니다.

최종 성능 발표

기여도 10%

최종 리더보드 결과, 모델 최적화 과정, Choice Shuffle 적용 전후의 성능 차이를 정리해 발표했습니다. 단순 결과 공유가 아니라 어떤 실험이 성능 개선에 영향을 주었는지 흐름 중심으로 설명했습니다.

사용 기술 및 선택 이유

Qwen3-VL (32B)

이미지 이해와 언어 추론을 동시에 수행할 수 있는 대규모 VLM이 필요했기 때문에 사용했습니다. VQA 태스크에서 이미지-질문-선택지 간 관계를 해석하는 데 적합했습니다.

PyTorch

모델 로딩, 추론 파이프라인 구성, 실험 조건 변경이 유연해 반복 실험에 적합했습니다. 다양한 모델/토크나이저와의 연동도 용이했습니다.

Unsloth

대규모 모델의 양자화 및 파인튜닝 효율을 높이기 위해 사용했습니다. 제한된 GPU 메모리에서 실험 가능한 구조를 만드는 데 도움이 되었습니다.

LoRA / QLoRA

전체 파라미터를 업데이트하지 않고 일부 어댑터만 학습해 메모리 사용량을 줄이기 위해 선택했습니다. 정확도와 자원 효율 사이의 균형을 잡는 데 적합했습니다.

주요 문제 해결 사례

문제 1. 32B 모델을 제한된 VRAM에서 구동하기 어려움

상황: 32B급 모델은 원본 상태로 로딩할 경우 VRAM 사용량이 커서 실험 반복 자체가 어렵고, 배치 크기나 입력 길이를 조금만 늘려도 메모리 부족 문제가 발생했습니다.

해결: 4-bit 양자화를 적용해 모델 파라미터 메모리 사용량을 줄였습니다. 또한 비전 레이어는 고정하고 언어 모델 레이어에만 LoRA 어댑터를 적용해 학습/추론 부담을 낮췄습니다. 실험 과정에서는 입력 프롬프트 길이와 max token을 조절하며 메모리 사용량과 출력 품질의 균형점을 찾았습니다.

결과: VRAM 사용량을 약 70% 절감하면서도 32B 모델의 추론 성능을 유지할 수 있었습니다.

핵심 판단: 전체 모델을 무리하게 조정하지 않고, 비전 레이어 고정 + 언어 레이어 LoRA 적용으로 자원 효율을 확보.

문제 2. 보기 위치에 의존하는 Position Bias 발생

상황: 평가 결과를 분석하는 과정에서 모델이 이미지와 질문의 의미를 충분히 보지 않고 특정 보기 위치를 반복 선택하는 경향이 관찰되었습니다. 이는 리더보드 점수는 올릴 수 있어도 실제 일반화 성능에는 위험한 패턴이었습니다.

해결: 데이터 로더에서 선택지 순서를 무작위로 섞고, 섞인 순서에 맞춰 정답 인덱스를 다시 매핑하는 Choice Shuffle 로직을 적용했습니다. 이후 동일 샘플을 여러 순서로 테스트하며 모델이 선택지 위치가 아니라 의미적 근거를 기준으로 답하는지 확인했습니다.

결과: 위치 편향을 줄이고, 기준 대비 정확도를 4.8% 향상시켰습니다.

핵심 판단: 모델 튜닝만이 아니라 데이터 로딩 단계의 편향 제어가 성능 개선에 직접적으로 기여.

문제 3. 모델 출력 형식이 일정하지 않아 자동 채점 안정성이 낮음

상황: 모델이 선택지 번호만 출력하지 않고 설명 문장까지 함께 생성하거나, 답변 형식이 샘플마다 달라지는 문제가 있었습니다. 이 경우 실제 정답을 맞혔더라도 자동 채점 과정에서 오답 처리될 수 있었습니다.

해결: 프롬프트에 답변 형식을 명확히 지정하고, few-shot 예시도 동일한 형식으로 구성했습니다. 후처리 단계에서는 정규표현식을 사용해 모델 응답에서 최종 선택지만 추출하도록 정형화했습니다.

결과: 출력 파싱 실패를 줄이고, 실험 결과를 안정적으로 비교할 수 있는 평가 파이프라인을 확보했습니다.

+4.8% Choice Shuffle 적용 후 정확도 향상

핵심 성과: 32B급 멀티모달 모델을 제한된 자원에서 운용 가능한 형태로 최적화하고, 데이터 편향 완화를 통해 정확도까지 개선.

회고

이 프로젝트를 통해 모델 성능은 단순히 더 큰 모델을 사용하는 것만으로 결정되지 않는다는 점을 체감했습니다. 제한된 자원 안에서 어떤 레이어를 고정하고, 어느 부분에 어댑터를 적용하며, 어떤 출력 형식을 강제할지 결정하는 과정이 실제 성능과 운영 안정성에 큰 영향을 주었습니다.

또한 데이터 편향을 발견하고 이를 로더 단계에서 제어한 경험은 이후 프로젝트에서도 중요한 기준이 되었습니다. 좋은 모델을 고르는 것뿐 아니라, 모델이 어떤 근거로 답을 내는지 확인하고 실험 설계를 개선하는 역량의 중요성을 배웠습니다.
