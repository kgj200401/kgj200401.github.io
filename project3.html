Project 03

NightWatch 야간 자율순찰 시스템

자율주행 로봇, 비전 AI 탐지, GPT-4o 관제 리포트, Web 대시보드를 연결해 야간 사각지대의 이상 상황을 자동 감지하고 기록하는 보안 관제 시스템을 구현한 프로젝트입니다.

프로젝트 기간

2026.03 ~ 2026.04

사용 기술

ROS2 Humble Nav2 Gazebo TF2 YOLO11n EfficientNet-B0 GPT-4o FastAPI Flask React

프로젝트 목표

야간 보안 환경에서는 새벽 시간대 범죄 집중, CCTV 사각지대, 저조도 화질 저하, 구두 보고 기반 기록 누락 문제가 함께 발생합니다. 발표자료 기준으로 야간 범죄 집중 발생률은 76%, CCTV 평균 사각지대는 3200m², 경보 후 평균 대응 시간은 48분으로 제시되었습니다.

목표 요약: 자율주행 순찰 → 비전 AI 탐지 → LLM 관제 리포트 → Web 대시보드 관제.

솔루션 구성

NightWatch는 로봇이 순찰을 수행하면서 카메라 영상을 ROS2 토픽으로 수신하고, 비전 AI가 사람과 자물쇠 상태를 탐지한 뒤, 이벤트 로그를 FastAPI 서버로 집계합니다. 이후 GPT-4o가 Markdown 형식의 보안 리포트를 생성하고, React 대시보드에서 실시간 영상과 이벤트 로그를 확인하도록 구성했습니다.

솔루션 근거: 자율주행 순찰, 비전 AI 탐지, LLM 관제 리포트, Web 대시보드 4개 축으로 시스템을 설계했습니다.

핵심 기능

동적 객체 3D 좌표 역산

카메라 토픽과 TF2 로봇 위치를 결합해 FOV 편차를 계산하고, 삼각함수 역산으로 감지 객체의 절대 X,Y 좌표를 추정했습니다.

3m 클러스터링 알림 제어

반경 3m 내 동일 좌표를 중복 감지로 판단해 동일 인물 재탐지로 인한 알림 도배를 제거했습니다.

GPT-4o 관제 리포트

사람 수, 자물쇠 상태, 발생 시간, 추정 좌표, 캡처 이미지를 구조화 JSON으로 변환하고 GPT-4o에 전달해 보안 리포트를 생성했습니다.

React + Flask 대시보드

ROS2 카메라 토픽을 Flask MJPEG 스트림으로 변환하고, React 대시보드에서 순찰 제어와 리포트 팝업을 제공했습니다.

역할 및 기여도

프로젝트에서는 ROS2 기반 자율주행/시뮬레이션, 비전 AI 탐지, 좌표 추정, 웹 연동 흐름을 함께 다루었습니다. 특히 카메라 좌표를 실제 맵 좌표로 연결하고, 탐지 결과를 웹과 리포트로 전달하는 통합 흐름에 집중했습니다.

ROS2 + Nav2 시뮬레이션

SLAM, Localization, Path Planning과 Gazebo 시뮬레이션을 연결해 순찰 로봇의 이동 흐름을 구성했습니다.

비전 AI 파이프라인

YOLO11n으로 사람/자물쇠 위치를 탐지하고, EfficientNet-B0로 locked/unlocked 상태를 분류하는 흐름을 구성했습니다.

좌표 추정 알고리즘

카메라 픽셀 기반 탐지 결과를 TF2와 로봇 방향 정보로 보정해 map 좌표계 위 실제 위치로 변환했습니다.

ROS-Web 통합

FastAPI/Flask 기반 REST API와 MJPEG 스트리밍 브릿지로 ROS 이벤트와 React 대시보드를 연결했습니다.

사용 기술 및 선택 이유

ROS2 Humble + Nav2

자율주행, 위치 추정, 경로 계획, 센서 토픽 처리를 하나의 로봇 시스템으로 묶기 위해 사용했습니다.

TF2 + 삼각함수 역산

2D 카메라 탐지 결과만으로 맵 위 실제 위치를 추정하기 위해 로봇 위치와 방향, FOV 편차를 함께 활용했습니다.

YOLO11n + EfficientNet-B0

YOLO11n으로 사람과 자물쇠 영역을 빠르게 탐지하고, Crop된 자물쇠 이미지를 EfficientNet-B0로 분류했습니다.

GPT-4o + React-Markdown

이벤트 로그와 이미지를 바탕으로 보안관제사 스타일의 Markdown 리포트를 생성하고 대시보드에서 바로 렌더링하기 위해 사용했습니다.

주요 문제 해결 사례

문제 1. 2D 카메라 탐지를 실제 맵 좌표로 변환해야 함

상황: 카메라에서 사람을 감지해도 단순 bounding box만으로는 순찰 맵의 어느 위치에서 이벤트가 발생했는지 알 수 없었습니다. 관제 리포트와 대시보드에 의미 있는 위치 정보를 남기려면 카메라 좌표를 map 좌표계로 변환해야 했습니다.

해결: ROS2 카메라 토픽, TF2 로봇 위치·방향, FOV 편차를 결합하고 sin/cos 변환을 적용해 절대 X,Y 좌표를 추정했습니다.

문제 2. 동일 인물 재탐지로 알림이 반복 발생함

상황: 같은 사람이 카메라에 계속 잡히면 매 프레임마다 새로운 이벤트로 기록되어 알림이 반복될 수 있었습니다.

해결: 반경 3m 안의 동일 좌표는 같은 이벤트로 묶는 클러스터링을 적용해 중복 알림을 제거했습니다.

핵심 판단: 탐지 정확도뿐 아니라 관제 UX를 위해 “같은 사건을 한 번만 알리는 구조”가 필요하다고 판단.

문제 3. ROS 카메라 토픽을 웹에서 실시간으로 확인해야 함

상황: ROS2 카메라 토픽은 로봇 내부 데이터 흐름에는 적합하지만, 웹 대시보드에서 바로 표시하기에는 변환 계층이 필요했습니다.

해결: Flask MJPEG 스트리밍 브릿지를 별도 서버로 분리해 ROS2 카메라 토픽을 HTTP 스트림으로 변환했습니다. React 대시보드에서는 순찰 시작/중지 명령을 FastAPI 엔드포인트로 전송하고, AI 리포트는 React-Markdown 팝업으로 렌더링했습니다.

핵심 기술 근거

좌표 역산 근거: 카메라 데이터 수집, TF2 위치 융합, 삼각함수 역산, 3m 클러스터링으로 중복 알림을 제거했습니다.

리포트 생성 근거: 이벤트 로그를 FastAPI에서 구조화 JSON으로 변환하고, GPT-4o가 Markdown 보안 리포트를 생성했습니다.

대시보드 근거: Flask MJPEG 브릿지, React 원격 제어, React-Markdown 리포트 팝업으로 순찰 관제 UI를 구성했습니다.

성과

3m 중복 알림 제거 클러스터링 반경
GPT-4o 멀티모달 관제 리포트 생성
MJPEG ROS 카메라 웹 스트리밍
ROS2 자율주행 순찰 통합

핵심 성과: 단순 탐지 모델이 아니라 탐지 → 위치 역산 → 중복 알림 제거 → 리포트 생성 → 웹 관제까지 이어지는 통합 순찰 파이프라인을 구성했습니다.

비전 AI 근거: 카메라 입력에서 YOLO11n Detection, 이미지 Crop, EfficientNet-B0 Classification을 거쳐 ROS2 토픽으로 결과를 publish했습니다.

회고

이 프로젝트에서 가장 크게 배운 점은 로봇 시스템에서는 AI 모델 성능만큼이나 좌표계, 시간 동기화, 웹 연동, 중복 이벤트 제어가 중요하다는 점입니다. 탐지 결과가 실제 관제 가치로 이어지려면 위치와 상황이 함께 기록되어야 했습니다.

특히 2D 카메라 기반 탐지를 맵 좌표로 역산하고, 3m 클러스터링으로 알림 도배를 줄이는 과정에서 모델 출력 이후의 후처리 로직이 사용자 경험을 크게 바꿀 수 있다는 점을 체감했습니다.
